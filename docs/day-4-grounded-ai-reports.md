# Day 4 grounded AI report pipeline

Date: 22 October 2026

Day 4 replaces the initial OpenRouter connectivity spike with a grounded report
pipeline. The browser sends a small, versioned measurement record. The server
validates phase order and timing, derives ranked observation candidates, and
allows generated prose to reference only those candidates.

## Data boundary

The report request contains handedness, marked phase snapshots, phase timing,
phase-level hand positions, pose availability, and confidence information. It
does not contain the video, images, raw landmarks, a client-authored
observation, or an analysis identifier.

The request schema requires address, top, and impact in chronological order;
finish remains optional. Timing must agree with the marker timestamps. Numeric
ranges, array sizes, recognised metric identifiers, and object properties are
validated at the route boundary.

## Candidate generation

A pure deterministic module builds at most three primary candidates and one
tracking-quality warning. It can describe tempo, pelvis movement, arm
structure, lower-body movement, image-plane body lines, and wrist-midpoint hand
path. Low-confidence measurements are excluded from primary observations.

Every candidate includes a stable ID, related phases and metrics, confidence,
numeric evidence with units, a deterministic observation, and conservative
context from the application knowledge catalogue. It never evaluates a swing
as good or bad and never represents wrist tracking as club tracking.

## Language-model boundary

OpenRouter receives only the selected server-built candidates. Its structured
response must provide one plain-language insight per candidate while preserving
the candidate IDs. The application rejects unknown or repeated IDs, omitted
candidates, digits, markup, links, unsupported club or ball claims, diagnoses,
absolute swing judgements, and prescriptive instructions.

Limitations are owned by the application rather than generated by the model.
They state that the result is single-camera and image-space, describe pose
tracking uncertainty, and explicitly exclude clubhead speed and ball flight.
Provider errors, timeouts, malformed output, and failed grounding validation
return the deterministic report with the same candidate and evidence model.

## Verification

Unit and route tests cover request bounds, phase and timing consistency,
client-candidate injection, deterministic ranking, low-confidence filtering,
evidence identity, prohibited output, provider failures, and fallback behavior.
Twelve fixed measurement scenarios exercise left-handed input, optional finish,
tracking gaps, unavailable metrics, and each movement category without making
live provider requests in CI.

Quota enforcement, caching, consent, and the final report interface remain Day
5 work.
